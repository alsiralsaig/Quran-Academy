# أكاديمية القرآن الكريم — منصة إدارة حلقات التحفيظ

منصة PWA بثلاث بوابات (الإدارة، المعلمات، الطلاب) + المصحف والأذكار والتفسير والمساعد الذكي.

**الإصدار 2.3.0** — البيانات محفوظة في قاعدة **Neon (PostgreSQL)** مع تسجيل دخول حقيقي وصلاحيات.

## البنية

| الجزء | المكان |
|---|---|
| الواجهة (React + Vite) | `src/` |
| سيرفر الـ API (دالة Vercel واحدة) | `api/index.ts` ← `server/app.ts` |
| قاعدة البيانات + إنشاء الجداول تلقائياً | `server/db.ts`, `server/schema.ts` |
| تسجيل الدخول (bcrypt + كوكي HttpOnly موقّع) | `server/auth.ts` |
| المساعد الذكي (Gemini من السيرفر فقط) | `server/ai.ts` |
| الاختبارات (Postgres حقيقي داخل الذاكرة PGlite) | `tests/api.test.ts` |

## النشر على Vercel + Neon

1. في Vercel: **Add New → Project** واختار المستودع (بيتعرف عليه كـ Vite تلقائياً).
2. في **Settings → Environment Variables** أضف المتغيرات (شوف `.env.example`):
   - `DATABASE_URL` — من Neon: **Connect** ← انسخ الـ connection string (pooled).
   - `AUTH_SECRET` — نص عشوائي 32 حرف أو أكثر.
   - `ADMIN_PHONE` و `ADMIN_PASSWORD` — حساب المدير (بيتنشأ أول مرة).
   - `GEMINI_API_KEY` — اختياري للمساعد الذكي.
3. **Deploy**. الجداول بتتنشأ تلقائياً مع أول طلب، والباقات والحسابات البنكية بتتزرع مرة واحدة.
4. افتح الموقع ← **دخول** برقم المدير وكلمة السر ← غيّر كلمة السر من قائمة الحساب.

> بديل: من Vercel → **Storage → Neon** بيربط القاعدة ويضيف `DATABASE_URL` تلقائياً.

## الصلاحيات

| | زائر | طالب | معلمة | الإدارة |
|---|---|---|---|---|
| الباقات، الحسابات البنكية، المعلمات المعتمدات | ✅ | ✅ | ✅ | ✅ |
| الاشتراك ورفع الإيصال | — | ✅ | — | — |
| رؤية الإيصال | — | إيصاله فقط | — | ✅ |
| تسجيل الحصص | — | — | طلاب حلقتها فقط | ✅ |
| اعتماد المعلمات والاشتراكات، الباقات، البنوك، الإعلانات | — | — | — | ✅ |
| كلمة سر مؤقتة لمن نسي، إيقاف حساب، تنزيل نسخة | — | — | — | ✅ |

- الدخول برقم التلفون (يقبل 09xxxxxxxx أو ‎+249… أو أرقام عربية، وأرقام دولية بالمفتاح).
- قفل مؤقت 15 دقيقة بعد 5 محاولات غلط.
- تغيير كلمة السر بيسجّل خروج الأجهزة التانية.
- رصيد الحصص ما بيتجاوز حتى لو الزر اتضغط مرتين (خصم ذرّي في استعلام واحد).
- صور الإيصالات بتتصغّر في الجهاز قبل الرفع (JPEG حوالي 1600px).

## التطوير المحلي

```bash
npm install
npm run dev:api   # سيرفر الـ API على 3001 — بدون DATABASE_URL بيستعمل PGlite في الذاكرة
npm run dev       # الواجهة على 3000 (بتحوّل ‎/api للسيرفر)
npm run check     # فحص الأنواع + الاختبارات
```

حساب المدير التجريبي محلياً (لو ما حددت ADMIN_PHONE): `0900000000` / `admin123`.

## تطبيقات الأندرويد

3 تطبيقات منفصلة بتفتح نفس الموقع، وكل واحد مقفول على بوابته:

| التطبيق | الحزمة | البوابة |
|---|---|---|
| إدارة إتقان | `sd.itqan.admin` | الإدارة (دخول بس) |
| معلمة إتقان | `sd.itqan.teacher` | دخول المعلمة + انضمام معلمة جديدة |
| طالب إتقان | `sd.itqan.student` | دخول الطالب + حساب طالب جديد |

- التطبيق بيعرّف نفسه في الـ User-Agent بـ `ItqanApp/<role>`، والموقع (`src/lib/appFlavor.ts`) بيخفي البوابات التانية. لو زول دخل بحساب دور تاني بتظهر ليهو رسالة وزر خروج.
- للتجربة في المتصفح: `?app=teacher` (والرجوع للوضع العادي: `?app=web`).
- أي تحديث للموقع بيوصل التطبيقات براهو — ما محتاج APK جديد إلا لو اتغيّر كود الأندرويد نفسه.
- البناء (بدون Gradle): `KEYSTORE=... KS_PASS=... ./android/build.sh` — المخرجات في `/home/user/apk`.
- **مفتاح التوقيع لازم يتحفظ**: بدونه ما بتقدر تنزّل تحديث فوق التطبيق المثبّت.

## سجل التغييرات

### 2.3.0 — تطبيقات الأندرويد
- 3 تطبيقات APK (إدارة / معلمة / طالب) بأيقونات وألوان مختلفة، مع رفع الإيصالات من المعرض، تسجيل التلاوة بالمايك، فتح واتساب وزووم والروابط الخارجية في تطبيقاتها، صفحة «ما في اتصال»، وزر الرجوع.
- وضع التطبيق المقفول على الدور في الموقع.

### 2.2.0 — المرحلة الثالثة
- **مواعيد الحصص** (جدول `scheduled_sessions`): المعلم يجدول حصة لطالب أو لكل طلابه، يوصلهم إشعار، ويدخلوا برابط حصة المعلم بزر واحد.
- **المكتبة الرقمية** (جدول `library_items`): المعلمين والإدارة يضيفوا كتب وفيديوهات وصوتيات كروابط https، مع بحث وتصفية؛ المالك أو المدير بس يمسح.
- **الختمة الجماعية** (جدول `khatm_campaigns`): المعلم يفتح ختمة، والطلاب يحجزوا الأجزاء (بدون تكرار، الحجز ذري) ويعلّموها مكتملة؛ إشعار للمعلم عند اكتمال الثلاثين جزء.
- إخفاء غرفة القراءة الجماعية المباشرة لأنها محتاجة اتصال لحظي ما بيشتغل على Vercel serverless.
- النسخة الاحتياطية للمدير بقت تشمل الجداول الجديدة. 20 اختبار.

### 2.1.0 — المرحلة الثانية
- **البيانات الشخصية في القاعدة** (جدول `user_data`، مسارات `GET /me/data` و `PUT /me/data/:key`):
  الأهداف الأسبوعية، المراجعات السريعة، ملاحظات الآيات، سجل السور المحفوظة، تقويم الحفظ اليومي، وإخفاء عناصر الأرشيف — تتزامن بين الأجهزة.
  البيانات القديمة المحفوظة في المتصفح تُنقل تلقائياً مرة واحدة ثم تُمسح.
- **تنبيهات المعلم المباشرة** (`POST /notifications/send`): لطلابه المعتمدين فقط، وتظهر للطالب كإشعار منبثق حقيقي يتعلّم كمقروء.
- **رابط الحصة (Zoom / Meet):** المعلم يحفظه من لوحته، ويظهر كزر للطلاب المشتركين معه باشتراك معتمد فقط (مخفي عن الزوار وبقية الطلاب).
- **إزالة المحتوى الوهمي:** الإشعار المنبثق التجريبي، زر الاحتفال الوهمي، تقدّم الحفظ المعبّأ مسبقاً، أيام التقويم المنجزة وهمياً، قائمة الطلاب الوهمية في تنبيهات المعلم، الحلقات المؤرشفة الوهمية (الأرشيف الآن من الاشتراكات المكتملة فعلاً)، ومواعيد الحصص الوهمية في التقويم.
- **النسخ الاحتياطي:** صياغة صادقة — حفظ فوري في Neon، الاستعادة لنقطة زمنية من لوحة Neon، وتنزيل نسخة JSON كاملة (تشمل البيانات الشخصية).
- اسم المعلم الحقيقي في الشهادة والتقرير الشهري بدل الاسم الثابت.
